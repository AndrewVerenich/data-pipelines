Платформа A/B-экспериментов

Стек: Kotlin / Spring Boot, Apache Kafka, ClickHouse, dbt, Apache Airflow, Apache Superset

Продуктовая платформа экспериментов: генератор шлёт assignment, exposure и конверсии, хранилище считает метрики от факта экспозиции. Витрина показывает lift, доверительный интервал и sample ratio mismatch по каждому эксперименту.

Ключевые возможности:
- Генератор: assignment, exposure, конверсии, позднее прибытие событий, пересечение аудиторий, искусственный SRM
- Ingestion из Kafka через Kafka Engine + Materialized Views
- dbt: факт экспозиции, факты метрик, CUPED, guardrail-метрики
- Зерно факта — «пользователь × эксперимент × вариант», а не сырая конверсия
- Витрина результатов: lift, доверительный интервал, SRM, guardrails
- Airflow: слои dbt и проверки качества перед публикацией результатов
- Дашборд Superset по активным экспериментам


Логистический control tower

Стек: Kotlin / Spring Boot, Apache Kafka, ClickHouse, Grafana

Операционный контур доставки: симулятор рейсов пишет GPS-пинги в Kafka, ClickHouse собирает гексагоны H3 и SLA-витрины, Grafana показывает карту и рейсы вне SLA.

Ключевые возможности:
- Симулятор рейсов: пинги GPS, склады, геозоны, простой, опоздания
- Ingestion из Kafka через Kafka Engine + Materialized Views
- Гексагоны H3 и маршрутные агрегаты в ClickHouse
- Витрины: ETA, рейсы вне SLA, простой у склада, плотность спроса по гексагонам
- Grafana: geomap и таблица рейсов с нарушением SLA


Reverse ETL: брошенная корзина

Стек: Kotlin / Spring Boot, Apache Kafka, ClickHouse, dbt, Apache Airflow, PostgreSQL, Grafana

Активация аудитории «бросил оформление заказа»: события витрины собирают желаемое состояние членства, синк считает разницу с прошлым прогоном и доставляет enter, leave и update в мок email-сервиса. Покупка или истечение окна снимает человека с цепочки.

Ключевые возможности:
- Генератор: просмотры, корзина, оформление, заказ, поздние события, битый email
- Ingestion из Kafka через Kafka Engine + Materialized Views
- dbt: профиль клиента и аудитория abandoned_checkout как желаемое состояние
- Changelog синка: enter, leave, update относительно прошлого снимка
- Kotlin-воркер доставляет пачки в HTTP API email-сервиса, состояние членства лежит в PostgreSQL
- Идемпотентность по user_id, аудитории и версии: повтор после сбоя не создаёт вторую подписку
- Dead-letter для 429 и отклонённых строк, следующий прогон продолжается с места остановки
- Airflow: витрина, затем diff, затем доставка
- Grafana: лаг синка, размер пачки, ошибки, повторные доставки
